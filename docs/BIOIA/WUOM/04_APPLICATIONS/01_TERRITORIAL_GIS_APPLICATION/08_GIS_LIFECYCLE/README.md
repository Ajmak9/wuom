## Purpose

This folder documents **GIS Lifecycle** as a derived territorial GIS application inside BIOIA / WUOM.

Its function is to describe the operational flow that turns spatial data into territorial reading, orientation, decision and update.

This is not a foundational document.
It does not redefine BIOIA / WUOM.
It does not open respiration.
It does not activate WUOM as a general phase.

## Operational Definition

The GIS lifecycle is the process through which territorial information becomes operational knowledge.

It can be organized into six stages:

```text
1. Collect data
2. Clean data
3. Analyze data
4. Visualize data
5. Make decisions
6. Update the database
```

Each stage supports the next one.

If one stage fails, the territorial reading loses coherence.

---

## 1. Collect Data

The first stage gathers spatial information relevant to the territory.

It may include:

```text
points
lines
polygons
raster data
satellite imagery
LiDAR data
cadastre
climate data
environmental layers
mobility data
socioeconomic information
field observations
```

Data collection defines the initial field of reading.

Not every dataset is useful.

Only data that can be situated, verified and related can support territorial orientation.

---

## 2. Clean Data

Data cleaning prepares information so layers can work together.

It may include:

```text
correcting geometries
removing duplicates
resolving null values
normalizing attributes
verifying datum
verifying coordinate systems
checking units
correcting inconsistencies
documenting source and date
```

Without cleaning, analysis may appear precise while remaining structurally weak.

---

## 3. Analyze Data

Analysis turns data into relations.

It can include:

```text
spatial queries
overlay operations
buffers
spatial joins
aggregations
proximity analysis
pattern detection
temporal analysis
risk models
coverage analysis
```

At this stage, layers stop being isolated.

They begin to produce territorial reading.

---

## 4. Visualize Data

Visualization turns spatial relations into understandable forms.

It may include:

```text
thematic maps
dashboards
interactive viewers
territorial charts
3D models
time series
change maps
risk maps
```

Visualization is not decoration.

Visualization is making a territorial relation legible.

---

## 5. Make Decisions

Decision-making appears when territorial reading can orient action.

It may support:

```text
urban planning
territorial ordering
risk management
environmental protection
infrastructure
water management
public services
area prioritization
community intervention
```

A situated decision does not depend only on data.

It depends on relation, context, scale, memory and consequence.

---

## 6. Update the Database

The GIS lifecycle does not end with the decision.

After action, the system must be updated.

This includes:

```text
adding new data
recording changes
correcting outdated layers
updating indicators
documenting decisions
comparing previous and current states
preparing future readings
```

Without updates, GIS becomes a dead archive.

With updates, it maintains operational continuity.

## BIOIA / WUOM Reading

```text
BIOIA = living territorial field

GIS = structure that organizes and processes spatial data

WUOM = apparatus that reads relations, tensions and interdependencies

GIS Lifecycle = flow that keeps territorial reading operational
```

The GIS lifecycle does not replace BIOIA.

It does not replace WUOM.

It technically sustains applied territorial reading.

## Relation to Territorial GIS

Within the Territorial GIS line, the lifecycle connects previous modules:

```text
datum and coordinates
↓
topographic reading
↓
territorial calculation
↓
spatial operations
↓
visualization
↓
risk
↓
decision
↓
update
```

The lifecycle gives continuity to the application.

It prevents each module from remaining isolated.

---

## What This Layer Corrects

This layer avoids reducing:

```text
GIS to final map
data to accumulation
analysis to calculation
visualization to aesthetics
decision to technical output
territory to database
```

A GIS project does not end when a map is published.

It ends when the reading returns to the territory and updates the system.

---

## Operational Rule

Before accepting a GIS result as valid:

```text
verify data origin
verify cleaning
verify analysis
verify visualization
verify associated decision
verify later update
```

The quality of the result depends on the full cycle.
